# 管理 UI の仕様 (Rust 版)

作成日: 2026-11-14
状態: ドラフト (レビュー待ち)。承認までは、テストと実装に着手しない。
関連: [api.md](api.md) (A-1 のエンドポイント、A-6 の同時実行の上限)、[release.md](release.md)。Issue: `densuke/Agy-Virtual-Office#892` (親は #877)。

## 1. 目的と範囲

Python 版では、FastAPI の自動生成 `/docs` (Swagger UI) を、フィード URL の組み立てに使っていた。Rust 版は `/docs` を持たず、当面は CLI の `--generate-url` で代替している。その代わりになる、**最小の管理ページ 1 枚**を、サーバーのバイナリに埋め込んで配信する。

- 入力: 対象の URL と、オプション (`max_items`、`use_feed`、`feed_first`)。
- 出力: 組み立てた `/feed` の URL、コピー用のボタン、取得結果のプレビュー。

対象外: 認証、設定や履歴の保存 (#877 の決裁で「登録」は保存しない)、`user_agent` の指定、複数ページ、別プロセス・別言語 (Node など) の追加、`/docs` や `/openapi.json` の再現。

## 2. Issue (#892) の「見直す点」への答え

| 見直す点 | 答え |
|---|---|

| `api_base_url` (`https://auto.fuga.jp` が 502) | 管理ページは、`api_base_url` を使わず、**ページを開いたときのオリジン (`location.origin`) から、URL を組み立てる**。設定の値が壊れていても、影響を受けない。(CLI の `--generate-url` が使う設定の値は、別の件で、本仕様の範囲外。D-M5。) |

## 3. 要件 (EARS)

### M-1 有効にするかどうか

**Event**: サーバーの起動時
**Response**: 管理ページは、**既定で無効**。次のどちらかで有効になる。
- 起動の引数 `--admin`
- 環境変数 `FEEDGEN_ADMIN` が、`1` または `true` (大文字小文字を区別しない)。それ以外 (空文字を含む) は、無効。

引数と環境変数の関係は、「引数があれば有効。なければ、環境変数」。有効にしたときは、起動時のログに、`管理ページを有効にしました (/admin)` を出す。無効のときは、何も出さない。

**Why**: Caddy の規則が、誤って外れても、既定で `/admin` が存在しなければ、公開されない。`/feed` と `/health` だけが、公開の面になる。

### M-2 エンドポイント

**Event**: `GET /admin` を受けたとき
**Response**:
- **有効なとき**: `200`。`Content-Type: text/html; charset=utf-8`。本文は、埋め込んだ HTML。M-3 のヘッダを付ける。
- **無効なとき**: 今までどおり、`404`、本文は `{"detail": "Not Found"}` (パスが、存在しないのと同じ)。

`/admin/` (末尾の `/`) と、`/admin` の下の別のパスは、どちらの場合も `404`。`GET` 以外のメソッドは、既存の規則どおり (`405`)。

### M-3 管理ページの応答ヘッダ

**Response**: 次のヘッダを付ける。
- `Cache-Control: no-store`
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: no-referrer`
- `Content-Security-Policy: default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`

ページは、**外部のリソース (CDN、フォント、画像、解析のスクリプト) を一切読まない**。スクリプトとスタイルは、HTML の中に、インラインで持つ (ファイルを分けない。KISS)。

### M-4 ページの入力

**Response**: 次の入力を持つ。

| 項目 | 内容 |
|---|---|
| 対象の URL | 必須。`http://` か `https://` で始まること (違えば、組み立てずに、理由を表示) |
| 最大記事数 | 1〜100 の整数。空なら、指定なし (サーバーの既定の 20) |
| 既存フィードがあれば代理取得 | チェックボックス (`use_feed`) |
| 既存フィードを検出して、ヘッダに付ける | チェックボックス (`feed_first`) |

`user_agent` は、入力に持たない (指定しなければ、サーバーの既定の `feedgen-api/1.0` になる)。

### M-5 URL の組み立て

**Event**: 入力が変わったとき
**Response**: `{location.origin}/feed?{クエリ}` を、画面に表示する。クエリは、**`url`、`max_items`、`use_feed`、`feed_first` の順**に、**指定されたものだけ**を入れる。`max_items` は、空でなければ入れる。`use_feed` と `feed_first` は、**チェックされたときだけ** `=true` で入れる (CLI の `--generate-url` と同じ。api.md C-4)。値は、`URLSearchParams` で符号化する。

**Why**: 組み立てた URL は、貼り付けた先のフィードリーダーが、取りに来る URL。`/feed` は公開なので、ページを開いたオリジン (公開のホスト名) から組み立てた URL が、そのまま使える。

### M-6 コピー

**Response**: 「コピー」ボタンで、表示中の URL を、クリップボードにコピーする。成功か失敗かを、画面に表示する (クリップボードが使えない環境では、URL を選択状態にして、手でコピーできるようにする)。

### M-7 プレビュー

**Event**: 「プレビュー」ボタンを押したとき
**Response**: 組み立てた URL を、**同じオリジンへの `fetch`** で取得し、結果を表示する。
- ステータスと `Content-Type`。
- 成功 (200) のとき: 本文を XML として解釈し、フィードの題と、記事の一覧 (題、日時、リンク) を、**最大 20 件**表示する。解釈できなければ、その旨と、本文の先頭 (最大 500 文字) を表示する。
- `X-Existing-Feed-URL`、`X-Existing-Feed-Title`、`X-Existing-Feed-Type` があれば、表示する (`Title` は、`%XX` を復号して表示する)。
- エラー (200 以外) のとき: `{"detail": …}` の文言を表示する。
- 取得中は、ボタンを無効にし、二重の送信を防ぐ。通信の失敗 (ネットワーク) も、画面に表示する。

プレビューは、通常の `/feed` の呼び出しと同じ扱い (A-6 の同時実行の上限、A-5 の締切の対象)。

### M-8 表示の安全

**Response**: プレビューに表示する、取得先 (外部のサイト) 由来の文字列 (題、説明、日時、リンク、エラー文言、ヘッダの値) は、**常に、テキストとして表示する** (`textContent`)。`innerHTML` などで、HTML として解釈しない。リンクは、`http:` と `https:` のスキームのときだけ、クリックできるリンクにする (それ以外は、テキストのみ)。リンクには、`rel="noopener noreferrer"` と `target="_blank"` を付ける。

**Why**: 取得先の内容は、利用者 (管理ページを開く自分) が制御できない。`javascript:` のリンクや、HTML の混入で、管理ページの権限 (同じオリジン) で、スクリプトが動くのを防ぐ。

### M-9 公開の面 (Caddy)

**Response**: 本番 (e2) では、`Caddyfile` の `feedgen.fuga.jp` の中で、`/admin` を、許可した接続元以外には `403` にする。既存の `/docs` などの規則 (`@docs_denied`) と同じ書き方で、**`/admin` を有効にする前に**入れる。

```
@admin_denied {
	path /admin /admin/*
	not client_ip <D-M1 で決めた接続元>
}
respond @admin_denied 403
```

有効にする手順の最後に、**許可されていない接続元 (携帯の回線など) から `/admin` を開き、`403` になること**を確かめる。

### M-10 配備の順序

**Response**: 次の順で行う。順序を変えない。
1. 新しい版をリリースし、e2 で `update.sh` により更新する。**この時点では、`/admin` は無効** (環境変数なし)。`/feed` と `/health` は、これまでどおり。
2. `Caddyfile` に、M-9 の規則を入れる (バックアップ、`caddy validate`、`reload`)。外から `/admin` を開いて、`404` (サーバー側が無効なので) であることを確かめる。
3. `feedgen-rs.service` の環境に、`FEEDGEN_ADMIN=1` を足して (systemd のドロップイン)、再起動する。
4. 許可した接続元から `/admin` を開いて `200` と画面を確かめ、**許可していない接続元からは `403`** であることを確かめる。

**戻し方**: ドロップインの `FEEDGEN_ADMIN=1` を外して、再起動する (`/admin` が `404` に戻る)。Caddy の規則は、残してよい。

### M-11 版

**Response**: 機能の追加なので、版を `0.3.0` に上げる (release.md R-2。タグ付きリリースが作られ、e2 の `update.sh` が取り込める)。

## 4. 実装方針 (KISS)

- `crates/feedgen-server/src/admin.html` (1 枚。インラインの `<script>` と `<style>`) と、`crates/feedgen-server/src/admin.rs` (配信とヘッダ。HTML を `include_str!` で埋め込む)。
- `AppConfig` に `admin: bool` を足す (既定は `false`)。`router` は、`admin` が真のときだけ、`/admin` のルートを足す (偽のときは、ルートがないので、既存の `404` になる)。
- 起動の判定は、純粋な関数 `resolve_admin(arg: bool, env: Option<&str>) -> bool` にして、表のテストをする。`main.rs` は、引数 `--admin` と、環境変数を渡すだけ (配線。テストしない)。
- ページのスクリプトは、約 100 行以内を目安にする。ビルドの工程、依存、外部のリソースを足さない。
- `docs/specs/api.md` の A-1 の表に、`/admin` (任意で有効) を足す。README にも、起動の引数と環境変数、配備の順序を足す。

## 5. テスト方針

- **起動の判定** (表。軽い): 引数 `--admin`、環境変数 `1` / `true` / `TRUE` / `0` / `false` / 空文字 / `yes` / 未設定、引数と環境変数の組み合わせ。
- **Router** (偽の `FeedService`。通信なし。`tower::ServiceExt::oneshot`):
  - 無効のとき: `/admin` が `404`、本文が `{"detail": …}`。**`/admin` の応答に、管理ページの内容が含まれない**。
  - 有効のとき: `/admin` が `200`、`text/html; charset=utf-8`。M-3 の各ヘッダ (CSP の値を含む)。外部のリソース (`http://`、`https://` で始まる `src` / `href` / `url(`) が、HTML に含まれない。`/admin/`、`/admin/x` は `404`。`POST /admin` は `405`。
  - 既存の挙動が変わらない: `/feed`、`/health`、`/`、CORS、同時実行の上限 (有効、無効のどちらでも)。
  - 有効でも、`/` の JSON の説明に、`/admin` を載せるかどうかは、D-M4。
- **ページの中身** (最小。壊れたときに、すぐ気づける範囲): HTML に、入力の要素 (対象の URL、最大記事数、2 つのチェックボックス) と、`/feed` を指す記述がある。`innerHTML` を使っていない (M-8。単純な文字列の検査)。
- **ブラウザでの確認** (自動テストにしない。画面の細部と、ブラウザの API に依存するため。実装のときに、内蔵のブラウザで、実際に開いて確かめる): URL の組み立て (M-5 の例を、数件)、コピー、プレビュー (成功、エラー、`feed_first` のヘッダ、記事の表示)、`<script>` を含む題のフィードが、テキストとして表示されること (M-8)。確かめた内容は、PR に書く。
- **配備**: M-10 の確認 (4 つ) を、実際に e2 で行い、結果を、記録に残す。

## 6. 影響と、残るもの

- Caddy の規則を入れ忘れても、サーバー側が既定で無効なので、公開されない。**有効にしたのに、Caddy の規則が誤っていた場合は、公開される**。そのため、M-10 の 4 の確認 (許可していない接続元からの `403`) を、必須にする。
- Python 版の `/docs` の規則 (`@docs_denied`) は、Python 版を片づけるとき (release.md の段取り) に、Caddy から外す。
- `/admin` の存在は、`/` の JSON には載せない (D-M4)。

## 7. 未決事項 (推奨つき)

- **D-M1 許可する接続元**: 推奨: **既存の `/docs` の規則と同じ接続元** (自宅の固定 IP `221.247.29.226`、Tailscale の `100.64.0.0/10`、`fd7a:115c:a1e0::/48`)。#892 と #877 は「Tailscale 内のみ」としているが、`feedgen.fuga.jp` を、公開の DNS で開くと、接続元は、端末の公開の IP になり、Tailscale のアドレスにならない (exit node か、独自の名前解決を使う場合を除く)。`/docs` の規則も、同じ理由で、自宅の IP を含めているとみられる。**Tailscale のみにする場合は、使い方 (exit node など) を、あなたが決める**。
- **D-M2 既定の無効**: 推奨: 無効が既定 (M-1)。有効にするのは、本番だけ。
- **D-M3 版**: 推奨: `0.3.0`。
- **D-M4 `/` の JSON に `/admin` を載せるか**: 推奨: 載せない (公開の面に、管理ページの存在を示さない)。
- **D-M5 `api_base_url` の値**: 管理ページは使わないので、範囲外。CLI の `--generate-url` が使う設定の `https://auto.fuga.jp` (502 を返す) は、設定ファイルの側で、`https://feedgen.fuga.jp` に直すのが、推奨。どの設定ファイルかは、私には分からない (e2 の `config.yaml` か、手元か)。
- **D-M6 プレビューの件数**: 推奨: 20 件 (M-7)。
